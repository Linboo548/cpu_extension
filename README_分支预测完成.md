# 创新扩展：分支预测交接说明

这份文档供接手同学理解实现、制作答辩 PPT 和复现测试。课程设计说明 `计算机组成原理课程设计说明LA+2026.pptx` 把分支预测列为创新扩展选项，没有指定必须采用哪种算法。本仓库在本次交接前已有预测器 RTL 与流水线接入；本次工作补充测试并完成了功能回归，没有把已有代码误写成此次新开发内容。

## 1. 要解决什么问题

遇到分支指令时，CPU 在取指（IF）阶段还不知道分支是否成立，也不知道最终要从哪里继续取指。如果始终按 `PC+4` 取指，跳转成立后就要丢弃错误路径上的指令、重新取目标指令。分支预测让 IF 提前选择下一 PC；若后来证明预测错了，再纠正取指路径。预测必须保证程序执行结果不变，改善的只是部分程序的运行周期。

## 2. 本仓库怎样预测

- **BTB（分支目标缓冲表）**：32 项直接映射，用当前 PC 的部分位选表项。每项记录有效位、完整 PC 标签、目标地址、是否为条件分支，以及两位方向计数器。完整标签用于避免不同 PC 落在同一索引时误用旧目标。
- **条件分支 `BEQ/BNE/BLT/BGE/BLTU/BGEU`**：BTB 命中后，计数器的高位决定是否预测跳转。`00/01` 预测不跳，`10/11` 预测跳；跳转使计数器加一，不跳使其减一，到 `00` 或 `11` 后饱和。这样偶尔一次反常结果不一定改变预测方向。新分支首次训练为 `10`（实际跳）或 `01`（实际不跳）。
- **无条件跳转 `B/BL/JIRL`**：BTB 命中后预测跳到缓存的目标。`JIRL` 的目标由寄存器计算，目标变化时可能预测错，随后由 ID 纠正并更新表项。
- **未命中或取指 PC 未对齐**：不采用表中目标，按顺序地址 `PC+4` 继续取指。复位时所有 BTB 项失效。

## 3. 预测错时怎样保证正确

1. IF 查 BTB，选择预测的下一 PC；同时把这个预测值和当前指令、当前 PC 一起送到 ID。因此发生流水线阻塞时，比较用的仍是**同一条指令**的预测值。
2. ID 根据已前递的操作数判断真实分支条件，算出实际下一 PC：跳转时是目标地址，不跳时是 `PC+4`。
3. ID 比较“实际下一 PC”和“随指令保存的预测下一 PC”。相同则继续执行；不同则通知 IF 改取正确地址，并丢弃错误路径指令。预测跳但实际不跳、预测不跳但实际跳、预测目标地址错误，都由同一比较处理。
4. 只有 ID 指令有效且真正离开 ID 时才训练 BTB，避免阻塞期间反复训练。WB 阶段的异常入口或 `ERTN` 返回地址优先于普通预测纠错。

一条典型循环分支的过程是：第一次遇到该 PC 时 BTB 未命中，先顺序取指；ID 确认跳转后纠错并写入 BTB。后续循环中若分支持续跳转，IF 可提前从 BTB 取目标。循环退出时分支变为不跳，ID 再把下一 PC 纠正为 `PC+4`。这是设计过程示意，不是对每个程序都保证固定节省周期。

## 6. PPT 可按这个顺序讲

1. **问题与目标**：分支结果在 IF 尚未知，预测下一 PC 可减少部分错误路径取指；保证架构结果不变。
2. **结构图**：画出“IF 当前 PC → BTB 查询 → 预测下一 PC → ID 实际下一 PC 比较 → 错误时重定向”，标明 BTB 有 32 项、完整 PC 标签和两位计数器。
3. **算法与纠错例子**：用 `00/01/10/11` 四态解释方向变化，再讲一次循环持续跳转、退出时纠错的过程。
4. **验证与数据**：展示 `predictor`、`cpu_branch`、ex9 开/关的 PASS；把 180 与 143 周期及相同的 51 次写回放在同一页。
5. **范围与局限**：本次没有综合、时序分析或上板验证；32 项直接映射表会发生索引冲突，`JIRL` 目标变化会有预测代价。不要把单个基准程序的 20.6% 写成所有程序的平均加速。

PPT 可截取上述 `simulate.log` 中的 PASS 行和 CPU 周期对比行作为证据。原仓库的 `README_阶段一交付.md` 记录的是当时“初版待验证”的历史状态；本文件中的 D 盘实测结果是后续完成的验证，不要把两份文档的时间点混在一起。
